The Lovable "Play" flood (hundreds gated in minutes) was the cockpit's **client-side** `ArrivalGenerator('Continuous')` at sim-speed 8 — NOT the backend. The backend twin had the opposite bug: it went **sterile**.

**U6 fix (migrations `oq_u6_*` on otto-q-core / gxdrcyphqjzjsuhxuqtg, 2026-06-19):** `ottoq_sim_advance_tick` never ran the twin's fleet-dispatch step, so OTTO-Q-released vehicles (`decide_tick` → `en_route_to_deployment`/`staged_for_departure`) never became real trips that RETURN as arrivals → depot drained to ~90% en_route/staged, 0 dispatches, 0 charging. Fix: advance_tick now calls `ottoq_sim_auto_dispatch_tick` (twin demand-gen, **gated OFF the benchmark depot** slug `benchmark%`), auto_dispatch now also consumes `en_route_to_deployment`, and `ottoq_sim_run_scenario` calls new `ottoq_sim_prime_deployment` (sends ~50% out at start with **staggered/backdated returns** → paced arrivals from t0). Separation held: twin owns dispatch+return (arrivals); OTTO-Q only releases. Production (uses `ottoq_world_advance`, not advance_tick) is untouched.

**Linchpin FIXED (migration `oq_u6b_proposer_charger_aware`, 2026-06-20):** the bug was in `ottoq_l2_propose_stall_assignment` (the L2 stall proposer that `decide_tick` §3 delegates to) — it picked the lowest-`id` free stall with **no charger-health check**, so when that stall sat on a Faulted charger EVERY arrival got proposed the same dead stall, the shield fail-closed on **HW.002.charger_state_precondition**, and ~23 healthy stalls sat idle (gate climbed to 50+, ~85 built/~4 enacted, charging died to 0). Fix: the proposer now only offers stalls whose linked charger is `station_state='Available'` + heartbeat-fresh (passes HW.002) and connector-compatible (passes HW.001). **Proposal-quality change only — the L1 shield is untouched (Simplex safety identical).** Verified: gate bounded (~11–20), charging sustained 7–16/tick, **0 HW.002 overrides** (was 316), 64 stall-assignments enacted, depot flows + drains. Depot facts: 45 charging stalls (10 dcfc/35 l2, all `Multi` supporting CCS1+NACS), ~11/45 chargers Faulted at any time (realistic), service_max_kw=2500 (energy never the limiter). **Backend now "100% tight", validated under normal_day AND aggressive_fleet_turnover wave (migrations `oq_u6c`–`oq_u6f`, 2026-06-21):** (U6c) added `ottoq_sim_recover_chargers` — `Faulted` was an ABSORBING state (HW.002 blocks new sessions on a faulted charger so it never completes one to clear) → every charger eventually died → total charging collapse; now repaired after ~50min. Plus high-SoC arrival triage (arrived_at_gate SoC≥85 skip charging → disposition). (U6d) `ottoq_sim_wash_triage` — wash on a CADENCE (~1-in-4 cycles via per-vehicle `cycles_since_wash` counter) instead of every cycle, so the 3-bay wash lane isn't swamped (was 89-deep `charge_complete_holding`); OTTO-Q still owns wash admission. (U6f) THE charger-collapse root cause: `ocpp_sessions.updated_at` was stamped real `NOW()` but elapsed = `sim_clock_now - updated_at`; advancing many sim-ticks in seconds made the sim clock run hours ahead → 2nd+ advance saw elapsed≈hundreds-of-min → fault prob ≫1 → every multi-tick (L2) session faulted. Fixed: stamp `updated_at` with the SIM clock + cap elapsed at 90min; fault baseline 0.005→0.0012/min (depot chargers ~95-98% uptime). **Validated result (wave, tick 30): 44/45 chargers Available, gate 0, wash queue 0, charging active, fleet cycling at 75% deployed — no unbounded queues.** All these are advance_tick world-phase / twin-physics changes; `decide_tick` safety logic untouched; benchmark depot still skips the dispatcher. Remaining B0: B0.5 scorekeeper refresh (re-run OTTO-Q vs baselines now the depot flows). Then Phase C cockpit (Play→backend rewire + dropdown + motion).
