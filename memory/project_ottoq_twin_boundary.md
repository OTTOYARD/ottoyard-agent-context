The decision doc is `docs/OTTOQ-TWIN-BOUNDARY.md` — **not in `OTTO-Q V1`**. It lives on an UNMERGED branch of `ottoyarddepot-sim`: `claude/simulation-data-otto-q-4p7450` (HEAD `8a582ee`, 2026-07-28). Fetch with `git fetch origin <branch>` then `git show FETCH_HEAD:docs/OTTOQ-TWIN-BOUNDARY.md`. It is one branch deletion from gone — merge it or copy it somewhere durable.

Its plan: (1) separate `twin`/`ottoq` schemas inside one DB + real command ingest + revoked cross-schema write grants, (2) prove instructions flow, (3) OTTO-Q to its own service, (4) split DBs, (5) point at a physical depot.

## Audit verdict, 2026-07-28 (17-agent adversarial audit vs live gxdrcyphqjzjsuhxuqtg)

**Step 1's revoke would be cosmetic today.** Three independently sufficient blockers:
1. **47 SECURITY DEFINER world-state writers all owned by `postgres`** (`rolbypassrls=true`) — they ignore RLS and any REVOKE. Includes `ottoq_decide_tick`, `ottoq_reserve_stall`, `ottoq_world_advance`. All EXECUTE-able by `anon`.
2. **No privilege separation to revoke from.** A policy named "Service role full access" on 34 tables (incl. `vehicles`, `stalls`, `depots`) is actually `TO PUBLIC USING(true) WITH CHECK(true)`; `anon` holds INSERT/UPDATE/DELETE on 180 objects; the anon key ships in the client bundle. The two roles a boundary needs do not exist.
3. **search_path.** PostGIS lives in `public` (744 functions). 98 functions pinned to `search_path=public, extensions` hard-break on a move; 281 are unpinned and would *silently* misresolve — which makes a phased migration MORE dangerous than big-bang.

Plus: **408 migrations in the DB, 1 migration file in the repo** — no dry run, no reviewable diff, no rollback but PITR. Dump `pg_dump --schema-only` into the repo before any DDL. 5 active cron jobs (4 hardcode `public.`).

NOT blockers (drop from planning): realtime (the `supabase_realtime` publication has zero public tables), cross-schema FKs (legal, survive), materialized views (zero).

**Cheapest real enforcement, available now:** `ottoq_events` already blocks UPDATE/DELETE with a BEFORE trigger regardless of grants. The same trigger pattern on `vehicles.current_stall_id` / `stalls.current_vehicle_id` makes rule 1 (OTTO-Q never writes world state) real without any schema DDL.

## Rule-1 violation, precisely
`ottoq_decide_tick` runs 8 direct `UPDATE vehicles` / `UPDATE stalls`, reached from the declared endpoint `ottoq_api_otto_q_decide`. The commands are **receipts, not instructions**: the UPDATE precedes the emit in the same transaction (26,072 of 32,723 rows, 79.7%). Target pattern already exists in-house — `ottoq_energy_orchestrate` writes only to `ottoq_energy_commands`, never world state.

## Rule-2 (refusal) state
`ottoq_vehicle_commands.status` CHECK already allows `'refused'`; `ottoq_ack_vehicle_command` accepts refusal + free-text reason (stuffed into `payload->>'ack_reason'`, no column). **It has never fired: 31,157 executed, 1,566 issued, ZERO refused/confirmed/expired, ever.** Cause: `ottoq_sim_confirm_commands` stamps `executed` unconditionally after a 1-3 sim-min delay — no refusal branch. Hard prerequisite: `ottoq_emit_vehicle_command` RETURNS void, so OTTO-Q never learns the `command_id` and cannot correlate a refusal to a decision.

Vocabulary should be derived, not invented: `ottoq_rule_evaluations` is already the right shape (closed `rule_code` + free-text `reason`) with 11,095 real blocks; and the `exception_type` enum already contains `vehicle_unresponsive` and `safety_concern`.

## ⛔ RULE-1 INVERSION — DESIGNED, ADVERSARIALLY REVIEWED, VERDICT = **DO NOT ATTEMPT YET** (2026-07-30, workflow wf_7332da9a-3a1, 7 agents)
Two independent plans both self-rated ATTEMPT_WITH_CONDITIONS; **3 of 4 adversarial reviewers returned REJECT.** The goal is right; the sequencing was wrong. Do not retry the naive "delete the UPDATEs, set apply_required" approach.

**⭐⭐ THE ONE FACT THAT DECIDES IT — the actuation window is 10-30× larger than anyone assumed.** `ottoq_sim_confirm_commands` runs at the **TOP** of the world pass and `ottoq_decide_tick` runs **LAST** (via `ottoq_sim_decide_and_dispatch`), in BOTH `public.ottoq_sim_advance_tick` and `twin.ottoq_world_advance`. So a command emitted at tick N is first *examined* at tick N+1. Measured: `tick_interval_seconds=30 × time_scale=60` ⇒ **30 SIM-MINUTES per tick** (run 7f36ce3e: 48 ticks = exactly 24 h). The 1-3 min CRN delay is entirely swallowed by the tick period. **Every risk rating in both plans was scored against 1-3 minutes and is therefore unscored.**

**The other seven killers:**
1. **Reservations die mid-flight** — begin_charge reserves 600 s, staging sites 900 s, against an 1800 s window; `ottoq_reserve_stall` never renews. The stall claim is the ONLY in-flight protection either plan cited (`reservation_stays:true` on all sites).
2. **No apply-time re-validation** — the executor's occupy is unconditional (`UPDATE stalls SET current_vehicle_id=…, status='occupied' WHERE id=v_stall_id`); `ottoq_validate_assignment` runs **PRE-FLIGHT only**. Today emit≈apply so pre-flight *is* apply-time; inversion breaks that identity.
3. **⚠️ THE SAFETY NET IS BACKWARDS.** `idx_stalls_one_vehicle_per_stall` is `UNIQUE ON stalls(current_vehicle_id) WHERE NOT NULL` — it enforces **one STALL per VEHICLE**, the opposite of its name. It structurally *cannot* detect two vehicles claiming one stall. The evicted vehicle keeps a dangling `current_stall_id` and so is invisible to `place_unplaced_vehicles` (whose cursor needs `current_stall_id IS NULL`).
4. **Same-tick reconciler race, certain not rare** — `ottoq.ottoq_place_unplaced_vehicles` runs ~2 statements AFTER `decide_tick` in the SAME `decide_and_dispatch` call, and its cursor (`current_stall_id IS NULL AND current_state IN (arrived_at_gate, staged_*, …)`) is *exactly* the in-flight population. It would re-park every decided vehicle, every tick, before the twin ever sees the order.
5. **52% is un-invertible today** — `stage`(175) + `enter_wash`(17) + `enter_service`(10) = **202 of 391 commands** carry no `stall_id`, and the executor's apply is gated `AND v_stall_id IS NOT NULL` with CASE arms only for charging_dcfc/l2/ELSE staged_awaiting_service. Flagging them `apply_required` marks them **'executed' while the world never moves**. `stage` is the redeploy gate ⇒ the depot silently stops sending cars out.
6. **A/B invalidation** — `decide_and_dispatch` routes greedy→`ottoq_greedy_tick`, fifo→`ottoq_fifo_tick`, manual→`ottoq_manual_tick`, ELSE→`decide_tick`. **decide_tick is the TREATMENT ARM ONLY, not a shared baseline** (corrects the boundary-doc framing). The baselines write instantly, so the latency tax lands only on OTTO-Q — structurally biased AGAINST the product. Also a full tick of charging is lost per placement (no charging state ⇒ no session ⇒ no energy) while `ottoq_claim_tick_kw` books the load at decision time ⇒ hits the **energy headline** specifically.
7. **Two latent silent kill-switches** — `confirm_commands` sits inside `IF v_feed_sim THEN` (`depots.feed_mode='sim'`) in BOTH engines, so the first depot flipped to a **live feed** freezes entirely, surfaced only as `RAISE WARNING`; and `ottoq_api_otto_q_decide` never calls confirm_commands (apply is the separate `ottoq_api_twin_apply_commands`), so decide-alone becomes a no-op depot. Also: any mandatory in-flight guard needs an **AGE CAP** — `world_advance` wraps the executor in `EXCEPTION WHEN OTHERS THEN RAISE WARNING`, so one swallowed error would permanently exclude those vehicles from all future decisions = silent depot-wide standstill with a green tick loop.

**✅ THE PREP IS SAFE AND ZERO-RISK — all twin/engine-side, valid while `decide_tick` still writes the world, no vehicle behaviour changes until the final flip.** Ordered: **(1)** add a SECOND `confirm_commands` call AFTER `decide_and_dispatch` in both engines, same transaction, decision-half-then-twin-half — collapses 30 sim-min → 1-3 min and *makes the whole risk model valid*; **(2)** apply-time re-validation, refuse with `target_taken_in_flight` so `ottoq_react_to_refusals` reroutes; **(3)** executor's vacate must also clear `reserved_by`/`reservation_expires_at` (today it doesn't ⇒ capacity leak that reads as phantom scarcity in [[project_charger_ratio_capex]]) + add the `svc_step` config channel; **(4)** raise TTLs above the window; **(5)** guard `place_unplaced_vehicles` WITH AN AGE CAP; **(6)** guard the two bare gate-disposition UPDATEs (`ottoq_sim_advance_tick_world` hardcodes `current_soc>=85` with NO stall guard); **(7)** settle A/B (move all four arms onto the bus, or freeze cross-policy claims and re-cert); **(9)** move `confirm_commands` outside the feed_mode gate; **(10)** clean the 4 `sim_run_id IS NULL` command rows. **THEN** invert smallest-site-first: L175-180 (emits nothing today ⇒ strict gain), then L234-256, then L199-209. **Leave L285-287 / L318-326 alone** until the executor can apply stall-less state changes.
**Keep `ottoq_reserve_stall` at every site — a reservation is a CLAIM, not a world mutation.**
