**Chase (2026-06-26), standing architectural principle:** "All 'real data feeds' — whether energy, vehicle telemetry, weather, charging-system faults, etc. — will be piped in / rotated via the OTTO-TWIN variable backend that we develop. So anything that needs to be tested for functionality for now should just be temporary until we are ready to pipe in the hyper-realistic data from the OTTO-TWIN world simulator to OTTO-Q."

**What this means:** OTTO-TWIN (the world simulator / variable backend) is the ONE upstream that generates + rotates every realistic input variable. OTTO-Q consumes those feeds, decides/optimizes, and the two cockpits (OrchestraAV manager, OTTO-PULSE technician) are thin clients reading the result. The current data sources on otto-q-core (`site_energy_snapshots`, the `ottoq_sim_*` twin functions, the `production_live` run + `ottoq-depot-tick` cron — see [[reference_live_data_model]]) are the **temporary precursor** to that full variable backend.

**Why:** keeps realism in ONE place (the twin), not scattered/hardcoded across OTTO-Q or the UIs — matches the mandate that the twin generates randomness/physics and OTTO-Q only reacts/optimizes. The hyper-realistic feed (telemetry, weather, faults, energy) is a build still ahead.

**How to apply:**
- Wire UIs + OTTO-Q to CONSUME the seam (the otto-q-core reads/endpoints), not to embed feed logic. When the OTTO-TWIN variable backend pipes richer data through the same seam, everything lights up with no rework. (The cockpit cleanup PRs field-ops#4 + a4359174#10 already follow this.)
- Treat test scaffolding (manual `production_live` runs, forced low-SoC waves, staged vehicles, A/B fork harnesses) as TEMPORARY — fine for proving functionality now; don't harden it as if permanent.
- For feeds that don't exist yet (vehicle GPS/odometer, etc.): show honest empty/placeholder states — do NOT fabricate. They arrive when OTTO-TWIN pipes them.
- Don't over-invest in permanent per-feed plumbing on the OTTO-Q/UI side before the twin variable backend defines the contract. Build the consumption pattern; let the twin fill it.
