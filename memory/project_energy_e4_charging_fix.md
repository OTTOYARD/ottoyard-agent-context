**2026-06-25 — DEEPENING (oq_fc_energy4–8): made the dial FINELY TUNABLE + fixed 5 real twin-execution bugs** (the FC-4 "coarse lever" finding — see [[project_frontier_core]] — is now resolved). The dial was coarse because the EV-throttle + battery levers were silently broken. Found via deep instrumentation (savepoint-fork CRN A/B + a temp debug table patched into the live fn). **The 5 bugs, all server-side `replace()`+guarded-EXECUTE patches on live `pg_get_functiondef`:** (1) **oq_fc_energy4 — charge-session FREEZE:** `advance_charge_sessions` computed per-tick elapsed from `ocpp_sessions.updated_at`, but trigger `trg_ocpp_sessions_updated`→`update_timestamp()` stamps it with REAL `now()`; whenever sim-clock≠wall-clock (every MPC fork, backtest, manual run) elapsed went negative → `CONTINUE` skipped EVERY session → charging frozen + throttle never ran. Fix: derive elapsed from the meter's own sim-stamped `last_meter_value->>'at'` (loop-controlled, trigger-immune). (2) **oq_fc_energy5 — BESS recharge not demand-aware:** the EV charge-cap credited only battery DISCHARGE (`GREATEST(dispatch,0)`), so when the battery RECHARGED it pulled grid power the cap ignored → EV+recharge blew past the demand target (saw 3224 kW = 1896 EV + 1278 recharge). Fix A: cap uses the SIGNED `+ v_bess_dispatch` (EV throttles to hold the line when the battery charges); Fix B: skip off-peak reserve recharge when a wave is forecast inbound. (3) **oq_fc_energy6 — snapshot lag:** `advance_site_energy` (inside `advance_all_energy`) ran at tick-step 3, BEFORE `advance_charge_sessions` at step 6 — so every snapshot paired THIS tick's battery dispatch with LAST tick's EV meters → phantom peaks in the very `grid_import_kw` billing reads. Fix: reordered charge physics to run before the snapshot. (4) **oq_fc_energy7 — throttle estimate inexact:** the throttle's `desired_load` used different battery-temp/noise-salt than the actual loop → under-counted demand. Fix: desired now mirrors the loop's rate formula exactly (same temp curve, clock-salted noise, elapsed>0 gate). (5) **oq_fc_energy8 — phantom un-throttled load (the big one):** `start_charge_session` opened each new session's meter at the FULL un-throttled rate `v_init_rate`; the loop then skips it (elapsed=0) so the cap never applies, but the snapshot bills it → every arrival wave injected un-throttled load that defeated the cap. Fix: new sessions open the meter at **0 kW** (OCPP meterStart=0; loop throttles from next tick). **RESULT (CRN savepoint-fork A/B, flagship):** the dial is now **monotonic + finely tunable + 0-unsafe** — peak grid tracks the demand target smoothly (e.g. 0.90/0.55/0.25 factor → ~1719/1373/623 kW, grid≈target), demand-aware recharge holds grid ≤ target (no phantom overshoot), and the EV smart-charging throttle bites even when the battery is depleted (1504→495 kW, −67%, 0 readiness penalty, 0 unsafe). Earlier high-load A/B (pre-deepening, realistic overnight wave) = 2509→983 kW (−61%). Headline holds + is now ROBUST: OTTO-Q caps the depot at a tunable demand ceiling; $ scales with the depot's peak (~$10k/mo at ~1000 kW @ $10/kW, more at higher demand-charge tariffs). NOTE: the sim manages load smoothly and actively re-dispatches manually-staged vehicles, so forcing a synthetic full-DCFC peak fights the engine — the mechanism is proven; the $ is load-dependent.
